# Подбор стратегий с Windows

`zapret_tuner.py` скачивает актуальные `general*.bat` из
[`Flowseal/zapret-discord-youtube`](https://github.com/Flowseal/zapret-discord-youtube),
фиксирует точный Git commit и разбирает BAT-файлы как данные. Скачанные
команды **никогда не запускаются**.

Тюнер переводит только разрешённые параметры zapret1 в nfqws2, добавляет
ограниченный набор router-native комбинаций и временно проверяет кандидатов
на Keenetic. Он не записывает:

- `/opt/etc/nfqws2/nfqws2.conf`;
- конфиги Xray/Mihomo;
- настройки XKeen;
- автозапуск.

Исходная служба nfqws2 восстанавливается через `EXIT` trap при нормальном
завершении, ошибке, потере SSH и `Ctrl+C`.

## Что потребуется

- Windows и Python 3.10 или новее;
- OpenSSH Client (`ssh.exe`);
- SSH-доступ к роутеру;
- уже установленные на роутере проект и `nfqws2-keenetic`;
- желательно SSH-ключ, чтобы не вводить пароль много раз.

## Самый простой запуск

Дважды щёлкните нужный файл:

```text
tune-youtube.bat
tune-discord-tcp.bat
tune-discord-voice.bat
```

После успешного подбора соответствующий BAT сохраняет отчёт сюда:

```text
reports\youtube-latest.json
reports\discord-tcp-latest.json
reports\discord-voice-latest.json
```

Тест временно перезапускает nfqws2 и может прервать затронутые соединения.
Перед началом нужно явно ввести `YES`.

## Только посмотреть кандидатов

Без SSH-подключения и без изменений на роутере:

```bat
python zapret_tuner.py youtube --plan-only --mix-level extended
```

Команду следует выполнять из каталога `tools\windows`.

## Случайный порядок и повтор прогона

Если `--search-seed` не указан, при каждом запуске создаётся новый seed:
меняется порядок кандидатов, а при небольшом `--max-candidates` — и
проверяемое подмножество. Перемешиваются только уже разрешённые стратегии;
расширенные рецепты остаются после основного пула.

Seed печатается в консоль и сохраняется в JSON-отчёт. Чтобы повторить тот же
путь на той же версии Flowseal:

```bat
python zapret_tuner.py youtube --search-seed 1732459012 --ref COMMIT_ИЗ_ОТЧЁТА
```

Диапазон seed: `0..4294967295`.

## Запуск с SSH-ключом и отчётом

```bat
python zapret_tuner.py youtube ^
  --router 192.168.2.1 ^
  --user root ^
  --ssh-key "%USERPROFILE%\.ssh\id_ed25519" ^
  --mix-level extended ^
  --report youtube-tuner-report.json
```

Отчёт JSON содержит источник, точный commit, seed и найденный результат.
Пароль роутера в него не записывается.

## Что проверяется

Windows и панель используют один router-runner. Перед перебором он записывает
baseline текущего профиля. Каждый проходной TCP-кандидат проверяется повторно:
YouTube — сайт, JSON oEmbed, миниатюра и дополнительная транспортная проба
googlevideo; Discord — сайт, gateway API и CDN-картинка. Проверяется ожидаемое
содержимое, а не только наличие HTTP-ответа. В `verification` JSON-отчёта
сохраняются этапы, время, объём, коды и причины отказа.

При Voice-переборе теперь сохраняются Discord TCP/QUIC и YouTube: заменяется
только голосовой профиль. Аналогично другие виды подбора сохраняют профили
остальных протоколов. Во временном firewall сохраняются их порты.

Voice остаётся с ручным подтверждением звука; UDP-наблюдения сохраняются
отдельно. Подробные границы тестов описаны в
[`../router/README.md`](../router/README.md).

### YouTube

Режим `youtube` автоматически проверяет TCP/TLS для YouTube, `youtu.be`,
`ytimg` и `googlevideo`.

Связанный QUIC-профиль выводится в результате, но HTTP3 не подтверждается
автоматически, если router curl не поддерживает его. После подбора проверьте
видео на реальном компьютере и телевизоре.

### Discord TCP

Режим `discord-tcp` проверяет сайт, gateway и CDN Discord по TLS.

### Discord Voice

Режим `discord-voice` открывает короткое окно для каждого UDP-кандидата:

1. отключитесь от voice-канала;
2. подключитесь снова;
3. посмотрите диагностику;
4. ответьте, заработал ли звук.

Сетевые счётчики подтверждают путь пакетов, но не качество аудио. До запуска
Discord TCP или Voice должен быть активен маршрут Xray `discord-direct`:
тюнер сам routing не меняет.

Маршрут должен быть доменным. Если в Xray снова появился
`ext:zkeenip.dat:discord`, runner остановится с ошибкой
`broad-discord-ip-selector-is-active`: широкая категория пересекается с
Cloudflare/Google и способна увести из VPN посторонний трафик.

## Глубина перебора

```text
--mix-level off       встроенный профиль + прямой перевод подходящих BAT
--mix-level safe      плюс одно контролируемое изменение за кандидата
--mix-level extended  плюс составные рецепты и смешивание BAT-компонентов
```

Для первого запуска используйте `safe`. `extended` полезен, когда прямые
кандидаты не сработали.

`safe` перебирает:

- TLS `out-range=-d4`;
- TLS fake `repeats=6`;
- `tcp_seq=-10000`;
- split `pos=1` и `pos=midsld`;
- `seqovl=5`;
- для YouTube QUIC — `repeats=6`;
- для Discord Voice — `repeats=2/3/11` и `out-range=<n3/<n4`.

`extended` дополнительно включает:

- TLS `out-range=-d2`, fake `repeats=2/11`;
- `pos=sniext+1`, `seqovl=1/681`;
- QUIC `repeats=3/11`;
- для Voice ограниченную матрицу `repeats=2/3/6/11` ×
  `out-range=<n2/<n3/<n4`;
- три заранее заданных составных TCP/QUIC-рецепта;
- одноосевые варианты до четырёх разных семейств из BAT и прежнее
  ограниченное смешивание fake/split.

Это не полный декартов перебор. Значения взяты из документированных
возможностей nfqws2, штатных примеров Zapret и актуальных Flowseal-профилей.
Неизвестные Lua-функции и shell-конструкции по-прежнему не допускаются.

Ограничить длительность:

```bat
python zapret_tuner.py youtube --max-candidates 12 --http-timeout 6
```

По умолчанию CLI проверяет до 32 кандидатов. Готовые BAT используют 48 для
YouTube, 40 для Discord TCP и 16 для Voice. Панель разрешает от 1 до 64.
Увеличение `max-candidates` линейно увеличивает длительность, а большие
`repeats` кратковременно повышают число fake-пакетов и нагрузку на nfqws2.
Повторный запуск без `--search-seed` начинает новый случайный путь.

Синтаксис диапазонов и Lua-параметров сверяется с
[`bol-van/zapret2`](https://github.com/bol-van/zapret2#readme).

## Что выводится при успехе

- исходный BAT-файл;
- Git commit и blob SHA;
- семейство стратегии;
- точные аргументы nfqws2;
- целевая переменная `NFQWS_ARGS`, `NFQWS_ARGS_CUSTOM` или
  `NFQWS_ARGS_UDP`;
- команды маршрутизации для Discord, YouTube или обоих сервисов.

## Как сделать результат постоянным

1. Откройте `http://192.168.2.1:8088`.
2. Переключите нужный сервис в `Zapret`, если он сейчас в `Direct/VPN`.
3. На вкладке **Импорт профиля** выберите JSON из папки `reports`.
4. Сначала нажмите **Проверить**, затем **Применить профиль nfqws2**.

Панель сохраняет профиль отдельно от генерируемого блока, поэтому следующий
обычный `apply` его не сотрёт. При применении перезапускается только `nfqws2`;
Xkeen не останавливается и не перезапускается. Для возврата есть кнопки
**Вернуть встроенный** и **Откатить последнее изменение**.

Ручная правка внутри управляемого блока `nfqws2.conf` по-прежнему не нужна.

## Альтернатива без Windows-тюнера

В панели `http://192.168.2.1:8088` есть вкладка **Автоподбор**. Она использует
тот же парсер, переводчик и временный runner, но запускает их фоновым заданием
непосредственно на роутере. Для YouTube и Discord TCP проверка автоматическая;
Discord Voice просит ответить **Да/Нет** после реального reconnect.

Найденный результат сначала только показывается. Постоянное применение
выполняется отдельной кнопкой и затрагивает только `nfqws2`.

## Восстановление кэша Discord

Во вкладке **Диагностика** панели можно скачать `reset-discord-cache.ps1`.
Запустите скачанный файл от имени своего обычного пользователя Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\reset-discord-cache.ps1
```

После подтверждения helper закроет Discord и переименует `Cache`, `Code Cache`
и `GPUCache` в резервные папки с суффиксом `.xkeen-backup-ДАТА`. Discord создаст
новый кэш при следующем запуске. Для отката закройте Discord и верните прежние
имена резервным папкам, предварительно убрав вновь созданный кэш. Сетевые
настройки и профиль пользователя Discord helper не меняет.

## Важные ограничения

- во время кандидата затронутые соединения могут кратко оборваться;
- потеря питания роутера не даёт `EXIT` trap завершиться, но после загрузки
  штатный init script стартует сохранённую постоянную конфигурацию;
- неизвестные и небезопасные winws-флаги отбрасываются;
- успешный TCP-тест не доказывает QUIC;
- успешные NFQUEUE counters не доказывают звук Discord Voice.
