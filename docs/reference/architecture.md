# Архитектура

## Путь трафика

```text
LAN → XKeen/Xray
        ├─ общий proxy outbound → VPN-сервер → ресурс
        └─ service-direct → WAN POSTROUTING → [nfqws2] → ресурс
```

Обычные transparent-входы завершаются явным Direct-правилом; VPN выбирается
доменно/IP-правилами и режимами сервисов. DNS и отдельный SOCKS-вход сохраняют
свои VPN-правила. Управляемые сервисные исключения стоят перед широкими
VPN-категориями CDN/IP; остальные пользовательские правила сохраняют порядок.

Новые служебные outbound-файлы используют `tail`. Перед записью проверяется,
что их добавление сохраняет исходный неуправляемый default Xray. Несовместимый
порядок файлов отклоняется до изменений; `04_outbounds.json` не переписывается.
Отдельный DSCP force-proxy путь исключён из обычных сервисных правил.

В Direct профиль nfqws2 выбранного сервиса выключен; в Zapret включён.
Xray остаётся частью управляемого Direct/Zapret, поэтому остановка XKeen
может оборвать соединение.

nfqws2 не обрабатывает внутренний TLS/QUIC ресурса внутри VPN-туннеля.
Пакеты забираются через Netfilter/NFQUEUE; неверный WAN/mark или offload,
обходящий Netfilter, может оставить стратегию без трафика.

## Разделение сервисов

Discord TCP выбирается доменами, Voice — Voice/STUN UDP-портами.
Общие CDN/IP-сети слишком широки для замены узкого списка Discord.
YouTube выбирается целевыми доменами; весь Google не должен автоматически
становиться одним управляемым сервисом.

TCP-порты:80,443,2053,2083,2087,2096,8443.
UDP:443,3478–3481,5349,19294–19344,50000–50100.
Wide Voice расширяет последнюю границу до65535; это захватывает больше трафика.
Для управляемого Telegram дополнительно используется5222.

## Ответственность компонентов

| Компонент | Назначение |
|---|---|
| Корневые .sh | Лаунчеры Python, не старый shell-движок |
| tools/router/kdn/engine | Подготовка, полный apply, импорт, откат |
| tools/router/kdn/web | Панель, API, фоновые задания и расписание |
| zapret_tuner.py + candidate runner | Перевод BAT и временные проверки |
| vpn_node_manager.py | Реестр и общий VPN outbound |
| tools/router/kdn/inspection + route_checker.py | Read-only RPC, проверка маршрута и ресурсов, наблюдение IP |
| kdn.web.domain.vpn_monitor | Отдельное расписание контроля активной ноды и допустимых IP |

Панель обслуживает UI, но проверка разрешения изменения выполняется заново
в backend под lock. Кэш UI не является основанием для мутации.

## Пути диагностических запросов

| Источник | Путь и назначение |
|---|---|
| Браузерные Standard/DPI | Текущая сеть компьютера; CORS ограничивает наблюдения |
| Проверка отдельной VPN-ноды | Изолированный Xray с её подключением; рабочий core не меняется |
| Чекер ресурсов Direct/VPN | Loopback SOCKS работающего Xray → заданный outbound → HTTPS |
| Контроль IP | Тот же VPN-путь к активной ноде; отдельные IPv4/IPv6 endpoints |
| Автоподбор | Собственные baseline/raw/candidate-пробы временного runner-а |

«Проверить маршрут» запрашивает `RoutingService.TestRoute`; это решение Xray
для заданного контекста, а не запрос к сайту. Пробы ресурсов закрепляют IP
назначения и source/local IP+порты, сохраняя исходные TLS SNI/HTTP Host и
проверку сертификата. Полные live settings сверяются с конфигурацией ноды;
совпадения одного outbound tag недостаточно.

Подготовка создаёт `99_kdn_inspection_tail.json` с двумя loopback SOCKS,
plain Freedom tail и узкими правилами перед обычной маршрутизацией. API по
умолчанию слушает `127.0.0.1:10085`, VPN SOCKS — `18445`, Direct SOCKS — `18446`;
совместимый существующий loopback API может иметь другой порт.
Включение доступа — отдельная транзакция с рестартом Xray на той же ноде.

`inspection-runtime.json` связывает corpus с PID/starttime рабочего процесса.
Внешний рестарт/редактирование делает его устаревшим; cached GET и IP approval
также проверяют свежесть. Сам монитор не переиздаёт подтверждение и не
перезапускает службы. Состояния и одобрение IP хранятся отдельно от стратегии
автоподбора: [порядок использования](../usage/route-checker.md).

## Конфиги и владение

Проект читает фактическую версию, init/runtime XKeen, Xray JSON/JSONC,
ports/marks/policy, nfqws2 config/lists, hooks, пакеты и runtime.
Меняются только управляемые блоки и необходимые ограничения портов/hooks.

DNS, proxy_router, DSCP, IPv6 и общие marks не переключаются ради подбора.
RCI-токен не создаётся автоматически.
04_outbounds.json принадлежит VPN-менеджеру и исключён из восстановления
обычного snapshot маршрутов. Прочие пользовательские правила сохраняются.

Транзакции и проверки: [безопасность](safety.md).
