# DNS домашней сети

## Режимы

На вкладке «Управление» переключается DNS-профиль сети Home:

| Режим | Путь |
|---|---|
| DNS over VLESS | `DnsVlessMain` → Xray `192.168.2.1:15355` → текущая VPN-нода → `1.1.1.1:53` |
| DoH на роутере | `DnsProfile0` → настроенные HTTPS-резолверы Keenetic |

**Перезапуск XKeen/Xray для смены этих режимов не нужен.** Оба пути уже
настроены; меняется только назначение профиля Home. VPN-нода, Xray/nfqws2,
профили Zapret, гостевая сеть и индивидуальные DNS-профили устройств сохраняются.
DNS самого роутера и собственный DoH браузера этим переключателем не управляются.

Выберите режим и подтвердите сохранение. Панель проверяет назначение повторным
чтением. Затем проверьте DNS и открытие сайтов с устройства Home: статус профиля
сам по себе не подтверждает доступность каждого резолвера или клиента.

## Резервный DNS

В разделе «VPN-ноды» включите **«Регулярный контроль»** и **«Резервный DNS»**.
По умолчанию оба выключены, интервал контроля — **5 минут**.
Сначала нужны [подготовка диагностики и одобрение выходного IP](../usage/route-checker.md#регулярный-контроль-активной-ноды).

Автоматический переход `VLESS → DoH` выполняется только после трёх подряд
подтверждённых отказов того же подключения и рабочего процесса:

- проверки завершены, выбран IPv4, одобрены допустимые IP;
- ни один из выбранных IP-endpoint не ответил через VPN, HTTPS-canary тоже не подтверждён;
- последнее наблюдение свежее, нода, конфиг и диагностический доступ не изменились;
- DNS Home всё ещё на VLESS, native-профили поддерживаются, recovery не ожидается.

Перед записью отдельное задание повторяет проверки. Недоступная диагностика,
`unapproved`, устаревшее наблюдение, занятость проекта, только IPv6 или отказ
одного сайта не запускают переход. Три неудачи считаются по результатам проверок,
а не по обновлениям страницы; это не обещание срабатывания ровно через15минут.

Если DNS уже на DoH, записи нет. **Автоматического возврата на VLESS нет:**
после восстановления VPN выберите его вручную. Нода и службы не переключаются.
Сообщение о переводе DNS отправляется только после подтверждённого завершения;
ошибка перехода требует ручной проверки. Настройка отправки — [ntfy](../usage/route-checker.md#уведомления).

## Защита и восстановление

Переключение использует общий project lock, фиксированные команды Keenetic и
приватный `dns-last-change.json`. При ошибке команды, проверки или сохранения
выполняется возврат прежнего назначения. При прерванной операции явно выберите
прежний режим для recovery; другие изменения блокируются.

Native save сохраняет **весь running-конфиг**, не только DNS. Не оставляйте
несогласованные правки в другом интерфейсе; на время таких работ отключайте
«Резервный DNS». Откат кода панели сам по себе DNS-профиль не возвращает.

Неизвестные профили, смешанные plaintext/DoH-upstream, изменения остальных
DNS-настроек или `proxy_router` не `off` дают отказ, а не перезапись.
Поддерживается существующая схема `Home` / `DnsVlessMain` / `DnsProfile0`.

Ручной переход на DoH не требует работающего VPN или диагностического API Xray,
но требует исправных Entware/XKeen2.1+ и native CLI. Автоматике, напротив,
нужен подтверждённый диагностический доступ: она не угадывает причину сбоя.

## CLI и API

Из каталога установленного проекта:

```sh
python3 -P tools/router/dns_mode.py --status
python3 -P tools/router/dns_mode.py --set doh --yes-router
python3 -P tools/router/dns_mode.py --set vless --yes-router
```

`GET /api/dns` только читает состояние. `POST /api/dns/doh` или
`POST /api/dns/vless` с JSON `{"confirm":true}` запускает фоновое задание.
