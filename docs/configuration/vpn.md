# VPN-ноды

WireGuard — экспериментальный импорт, не подтверждённая поддержка соединений.
На MIPS со сборкой Xray 26.11.9 userspace WireGuard может аварийно завершаться
ещё на `xray -test`. Не активируйте такой профиль без успешной проверки
установленного ядра. Сам импорт не меняет рабочий VPN.

Импорт: VLESS, Trojan, Hysteria2 и WireGuard (`wireguard://` / `wg://`
или один JSON outbound). Для WireGuard поддерживаются параметры `address`,
`publickey`, `presharedkey`, `dns`, `mtu`, `keepalive`, `reserved`, `allowedips`.
Имя берётся из фрагмента ссылки после `#`. Ключи base64 в ссылке должны быть
URL-кодированы. Для WireGuard принудительно включён `noKernelTun`: тестовый
и рабочий Xray не создают TUN-интерфейсы и таблицы маршрутизации.
IP/домен и порт можно менять отдельно; ключи и остальные параметры — заменой
ссылки или JSON. Добавление не запускает сеть, проверка и активация отдельные.

Одна активная нода меняет общий outbound `vless-reality`.
Все правила Xray с этим тегом используют выбранное подключение, не только
карточки панели. Независимые чужие outbounds не переписываются.
В реестре до 16 нод. Нужны Xray 26.10.31+ поколения 26, ctypes и Linux prctl.
Автобалансировки и автоматического выбора резервной ноды нет.

## Действия

| Кнопка | Результат |
|---|---|
| Добавить | Сразу сохранить резервную ноду без worker, пинга и активации |
| Пульс / Проверить все ноды | HTTP HEAD; массовая кнопка с иконкой пульса сверху, один временный Xray, до 4 параллельных замеров |
| Круговая стрелка сверху | Обновить список без запуска проверки соединений |
| Диагностика | Подробная проверка двух HTTPS-сайтов в отдельном задании |
| Редактировать | Имя, отдельные параметры или полная замена резервного подключения |
| Сделать активной | Проверка, private backup, замена общего outbound и рестарт XKeen/Xray |
| Восстановить прошлую ноду | Recovery после незавершённого переключения |
| Проверить текущую ноду | Выходной IPv4/IPv6 и HTTPS через работающий Xray; нужны подготовленные чекеры |
| Одобрить наблюдаемый IP | Явно сохранить свежие допустимые IP текущего подключения |
| Сохранить контроль и IP | Сохранить допустимые адреса, выбранные family, интервал и включение мониторинга |

Можно менять IP/домен, порт, SNI, fingerprint, Flow и дополнительные параметры
для текущего протокола/транспорта. Изменяются только отправленные поля;
остальные настройки и секреты сохраняются. Полная замена ссылкой/JSON — отдельно.

IP/домен, порт, SNI, fingerprint и Flow заполняются автоматически.
UUID, пароли, ключи и потенциально секретные транспортные строки не загружаются
в форму. Пустые дополнительные поля сохраняют прежнее значение.
После изменения подключения старый результат проверки сбрасывается.

Изменения активного подключения сохраняются отдельной резервной нодой
«… — правка». Действующий VPN не меняется. Проверка и «Сделать активной» —
отдельные действия с прежней транзакцией и откатом. Переименование активной
ноды не создаёт копию. При заполненном реестре сначала освободите место.

При добавлении имя берётся из `#имени` в ссылке, для JSON — из `tag`.
Без имени используется адрес сервера; совпадения получают числовой суффикс.
Переименование доступно в редактировании.

Совместимость для списка и операций с реестром кэшируется до60секунд с
инвалидированием по изменению файлов XKeen/Xray. Сам `outbounds` читается заново.
Перед применением подключения версии проверяются свежими командами.

## Быстрый HTTP-пинг

Модель замера соответствует [XKeen-UI](https://github.com/zxc-rv/XKeen-UI/blob/main/backend/src/healthchecker.rs):
первый HEAD прогревает туннель, второй измеряется по тому же keep-alive соединению.
Цель — `http://cp.cloudflare.com/generate_204`, до5секунд на запрос.
Запуск временного Xray и первый handshake не включаются в показанные миллисекунды.
Это не ICMP и не проверка HTTPS, YouTube или звонков. HTTP4xx показывает получение
ответа, но не успешную работу сайта. Пинг и диагностика хранятся отдельно.

При проверке всех нод используется один Xray с отдельными tunnel-входами,
явными правилами для каждой ноды и blackhole по умолчанию. Прямого fallback нет.
Рабочий Xray и его listener-ы не изменяются. Применение ноды по-прежнему включает
полную HTTPS-проверку, резервную копию и откат.

## Форматы

Карточка показывает endpoint, протокол, транспорт, TLS/Reality и заданные
flow/fingerprint/SNI. Отсутствующие дополнительные поля не показываются.
UUID, пароли, ключи Reality и исходная ссылка в карточку/API не передаются.
Активная нода при каждом обновлении читается из `04_outbounds.json`.
Если параметры файла изменились, старый результат проверки не показывается.
GET не записывает реестр и не применяет конфиги. Наличие параметров в файле
не доказывает, что работающий Xray уже загрузил их.

Импорт ссылок в панели использует исходный генератор
[XKeen-UI](https://github.com/zxc-rv/XKeen-UI/blob/ebb69f6a3fae039d2cfbc4a834b8b6e8513cb7be/frontend/src/lib/generator.js).
Он выполняется локально в браузере, после чего панель получает JSON outbound.
Ни ссылка, ни секреты не отправляются сторонним сервисам. Проверка соединения
запускается отдельно. Прямые CLI/API-вызовы со ссылкой используют ограниченный
серверный парсер; для одинакового результата передавайте сгенерированный JSON.

VLESS/Trojan URI или JSON outbound: TCP/RAW, WS, gRPC, XHTTP/SplitHTTP,
TLS/Reality и поддержанные поля безопасности.
Hysteria2: hy2:// или hysteria2://, auth, SNI/ALPN, pinning,
`obfs=salamander&obfs-password=…` (преобразуется в UDP finalmask Xray).
Полный finalmask передавайте JSON; диалекты ports/mport и другие obfs не угадываются.
Веб-импорт сохраняет параметры по правилам генератора XKeen-UI.
Ограниченный серверный URI-парсер отклоняет insecure=1, дубли/конфликтующие
aliases и неизвестные поля. Ссылки на другую ноду через proxySettings/dialerProxy
отклоняются и для JSON: такие ноды нельзя проверять изолированно.

## Проверка отдельной ноды

Изолированный Xray слушает localhost SOCKS; HTTPS-пробы идут через выбранный
outbound с remote DNS и ожидаемыми204/200. Proxy env/NO_PROXY/.curlrc
не должны превращать это в direct fallback.
Успех подтверждает эти запросы, не все приложения и протоколы.
В карточке есть «Подробности проверки», а результат также попадает в журнал
панели: транспорт ноды, проверка временного конфига, готовность локального
SOCKS, каждый HTTPS-запрос, ожидаемый/полученный HTTP-код, код curl и время.
Готовность SOCKS не доказывает успешный handshake с VPN-сервером.
Ошибки Xray классифицируются отдельно: WS Upgrade, TLS, DNS, соединение.
Сырые строки Xray/curl, URL с токенами и секреты не публикуются. Публичный
журнал ограничен 8KiB; временный Xray останавливается при журнале свыше128KiB.
Новый подробный журнал появится после следующего нажатия «Проверить».
«HTTPS, первый байт» — минимальное время до первого байта ответа из двух
HTTPS-запросов, включая установку соединения. Это не ICMP-пинг.
«Вся проверка» включает подготовку и запуск изолированного Xray и обе пробы.
Старые результаты без разделённых замеров показывают только общую длительность.

Есть таймауты и RSS-watchdog96MiB; это не жёсткий kernel memory limit.
Worker управляет только собственным тестовым PID. После SIGKILL могут
остаться private temp-файлы, но тестовый Xray не должен жить бессрочно.

## Контроль работающей ноды и выходного IP

Проверка отдельной ноды не доказывает, что действующий Xray уже использует её
настройки или выходит с нужного IP. Карточка **Контроль активной VPN-ноды и IP**
проверяет именно рабочий процесс и его полный outbound, затем наблюдает IP
через выделенный VPN SOCKS. Direct fallback и проверки резервной ноды отсутствуют.

Сначала явно подготовьте API/SOCKS в «Диагностике». Выполните свежую проверку,
одобрите IPv4/IPv6 либо введите допустимые адреса вручную, выберите контролируемые
family и сохраните настройки. До одобрения всех выбранных family монитор
включить нельзя. По умолчанию он выключен, интервал — 5 минут, допустимо 1..1440.

Ожидаемые IP связаны с ID ноды и параметрами подключения. Первое наблюдение,
смена подключения и ошибка не принимают новый IP автоматически. IP VPN-сервера
не равен выходному IP. IPv6 без результата остаётся непроверенным.
При явном одобрении IP или сохранении контроля удаляются одобрения отсутствующих
в реестре нод. Одобрения существующих нод сохраняются с прежней привязкой
к параметрам подключения.

После внешнего рестарта Xray, команды «Перезапустить» в блоке XKeen, ребута или изменения
его конфигов требуется повторная явная подготовка доступа. Монитор только
наблюдает и сохраняет историю: он не меняет ноду, службы, маршруты или стратегии
и не закрепляет IP у провайдера. Полный порядок и статусы:
[чекеры и VPN/IP](../usage/route-checker.md).

«Резервный DNS» — отдельный, по умолчанию выключенный переключатель. Он разрешает
переход Home с VLESS на DoH после трёх подтверждённых отказов VPN, без смены ноды
и рестарта служб. Условия и восстановление: [DNS](dns.md#резервный-dns).
Порог уведомления и защиты DNS различаются: не каждая неуспешная проверка
достаточна для автоматической смены DNS.

## Ошибки и хранение

Активный outbound читается из файла при каждом запросе; ручное принятие не требуется.
При ошибке активации выполняется откат. Незавершённый recovery блокирует
изменения/проверки; GET не запускает восстановление.

Итоговый JSON реестра ограничен 768KiB в UTF-8, включая форматирование.
Изменение сверх лимита отклоняется до сохранения; прежний реестр остаётся.

Каталоги0700, файлы0600. Отдельные пределы VPN:20 activation backups,
32 записи корзины,64 версии,16MiB на каталог. Pending recovery source защищён.
Это не политика30дней для снимков маршрутов и не UI восстановления удалённых нод.
