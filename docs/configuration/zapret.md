# Zapret: профили и подбор

## Разделение профилей

| Компонент | Трафик | Что подтверждает проверка |
|---|---|---|
| Discord TCP | TLS/TCP и QUIC по доменам Discord | Сайт/API/CDN, не голос |
| Discord Voice | Voice/STUN UDP | Сигнализация/UDP-проба или ручное подтверждение; не весь сеанс |
| YouTube TCP | HTTPS сайта и видео | Выбранные HTTP-пробы |
| YouTube QUIC | UDP443 | Отдельная UDP/клиентская проверка |

TCP, QUIC и Voice — разные стратегии. Во время Voice-подбора рабочий
Discord TCP-профиль должен сохраняться.
Профили из текста документа не являются активным конфигом устройства:
его смотрят в панели или через --print-nfqws-profiles.

BAT Flowseal преобразуются в nfqws2/Lua, а не запускаются на Linux.
Не все winws-флаги имеют точный аналог; неподдержанное не должно молча
считаться эквивалентным. TCP-перевод сохраняет повторы fake-пакетов внутри
`fakedsplit`/`hostfakesplit`, исходный default split-pos `2` и порядок zapret1
через `multidisorder_legacy`. Старые FORMAT1-профили автоматически не меняются.
Подробнее: [точность перевода](../../tools/windows/README.md#точность-перевода-flowseal).

## Сценарии перебора

В панели выбирают сервис, BAT-источник, сценарий Off/Safe/Extended и лимит
кандидатов. Seed генерируется автоматически; CLI позволяет задать его явно
для повторения порядка. Перемешивание меняет порядок, не критерии успеха.

Подбор использует исходные рецепты и допустимые вариации:
fake/multisplit/hostfakesplit, repeats, split positions, seq/seqovl,
fooling и out-range. Комбинации ограничены совместимостью рецепта;
это не произвольный полный декартов перебор всех флагов.
Подробные параметры интерфейса: [панель](../../tools/router/README.md#автоподбор-на-роутере).

При обычном ручном поиске найденный профиль показывается для отдельного
применения. Временный runner должен вернуть исходный nfqws2 после завершения,
ошибки или отмены. Voice может требовать ручного решения пользователя.

## Расписание

Только YouTube и Discord TCP. Время Europe/Moscow, например05:00 или03:00,15:00.
Отдельно выбираются сценарий, BAT и максимум кандидатов каждого ресурса.

1. Обновить BAT-источники с GitHub.
2. Дважды проверить работающий профиль теми же пробами, что ручной подбор.
3. При неудаче запустить выбранный перебор.
4. Применить найденный профиль, проверить снова, откатить при ошибке.

Расписание выключено до явного включения. Пропущенное время не догоняется.
При recovery-failed нужна ручная проверка.
Обновление BAT не обновляет автоматически все доменные/IP-списки
и не заменяет работающий профиль само по себе.

## Что можно заключить из проб

Роутерные baseline/raw/candidate — разные пути проверки;200 на baseline
и timeout на raw не противоречат друг другу.
Одинаковые пробы ручного/планового поиска не доказывают идентичный путь LAN.

Standard/DPI в диагностике выполняются из браузера. CORS может скрыть ответ;
HTTP4xx/timeout/DNS failure не доказывают IP/DPI-блокировку.
QUIC-unverified не равен отказу рабочего HTTP-профиля.

Отдельный [чекер ресурсов Direct/VPN](../usage/route-checker.md) работает с роутера
через подготовленные пути Xray. Он использует подходы dpi-detector для TLS/HTTP
и наблюдений TCP16, но не участвует в выборе кандидатов, оценке стратегий или
расписании автоподбора. Контроль VPN/IP также не запускает подбор.

После применения проверьте реальный Discord/YouTube.
Расширение Voice до65535 захватывает больше чужого UDP; не включайте его
как универсальное исправление. Общие CDN/IP-сети не заменяют узкий hostlist.

## Безопасное изменение

Меняйте один компонент за раз и сохраняйте пригодную точку отката.
Конфиг проверяется целиком: hostlists/blobs/Lua, покрытие портов, argv и queue.
--new отделяет следующий профиль; пустой профиль в начале не нужен.
Подбор временно перезапускает nfqws2, но не XKeen.
Запуск с компьютера: [Windows-тюнер](../../tools/windows/README.md).
