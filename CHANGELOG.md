# Изменения

## 3.2.0 — 22.10.2026

Исправления по [ревью 22.10.2026](docs/REVIEW-2026-10-22.md): ошибки, при
которых настройка одного сервиса ломала другой, а проверки этого не видели.

### Важно для роутера

- **Импорт профиля Discord TCP больше не включает QUIC-фейки для всего
  трафика.** Раньше движок обнулял `NFQWS_EXTRA_ARGS`, и стоковый
  QUIC-профиль терял список доменов. Теперь `NFQWS_EXTRA_ARGS` всегда
  `$MODE_LIST`, а `TCP_PORTS` при импорте — 443 и порты своих профилей.
- **При Discord TCP ≠ zapret стоковые профили больше не ловят весь HTTPS и
  QUIC.** Пустой `user.list` в nfqws2 значит «без фильтра»; теперь в нём
  `kdn-disabled.invalid`, а `NFQWS_ARGS_QUIC=""`.
- Режим legacy UDP: `fake` получил `blob=0x00000000` (без него стратегия 1
  ничего не делала).
- После обновления скриптов один раз выполните apply любого маршрута, чтобы
  переписать `nfqws2.conf`.

### Проверки

- `--check-config`: конфиг nfqws2 собирается тем же `_startup_args`, что и в
  init пакета, и проверяется целиком: порты очереди и фильтры профилей,
  профили без hostlist, пустые hostlist, `fake` без `blob`, диапазон Voice.
  `--print-nfqws-profiles` печатает собранные профили.
- Apply и импорт выполняют эти проверки и `nfqws2 --dry-run` до перезапуска
  nfqws2 и откатываются при ошибке. Перезапуск засчитывается только с новым
  PID, ожидаемой командной строкой, переходами iptables и портами NFQUEUE.
- Панель запускает проверки после каждой успешной операции: переключения,
  импорта, сброса, отката профиля, применения версии и результата подбора.
  **Проверить роутер** сверяет реальные правила NFQUEUE, отправляет QUIC
  Initial к YouTube с роутера, проверяет файл маршрутизации, который читает
  Xray, outbound'ы проекта и ретранслятор Telegram, ищет посторонние
  обходчики, предупреждает об IPv6 мимо nfqws2 и проверяет DNS через DoH.

### Автоподбор

- `tools/router/quic_probe.py`: настоящий пакет QUIC Initial (проверен по
  RFC 9001). YouTube-кандидаты проверяются и по QUIC; QUIC-секция больше не
  подбирается, кандидаты несут применённую.
- Проверка без обхода перед подбором, загрузка 64 КБ (виден обрыв на
  16–20 КБ), классы ошибок curl.
- nfqws2 восстанавливается при обрыве вывода (SIGPIPE) и после `kill -9`
  раннера; правила iptables кандидата проверяются перед каждым кандидатом;
  подбор и apply не идут одновременно (`FATAL|project-busy`).
- Исправлен перевод обмана Flowseal: `ts` → `tcp_ts=-600000`, `badseq` →
  `tcp_seq` + `tcp_ack=-66000`, только у фейков.
- Учитываются широкий диапазон Voice и blob Voice в режиме legacy.

### Откаты и состояние

- «Откатить последний импорт» больше не возвращает устаревший nfqws2 после
  переключения маршрутов.
- Записывается тег прокси-outbound (`# Proxy outbound: TAG.`).
- Обёртки на установке без XKeen не переводят роутер в режим с XKeen
  (`--integrated` — явный переход). Standalone apply сохраняет маршрут
  Telegram.
- Оборванное переключение в панели можно откатить из истории; панель не
  зависает, если процесс подбора умер.
- Старые снимки чистятся (`KD_SNAPSHOT_KEEP`, `KD_IMPORT_SNAPSHOT_KEEP`),
  `opkg update` ограничен по времени, перед заменой файлов делается `sync`.

### Telegram

- Ретранслятор помечает свои соединения меткой direct-outbound (`--mark`) и
  отключает прямой путь, если соединение вернулось в него петлёй.
- Сбой DNS роутера больше не выключает домены Cloudflare.
- Пополнение пула не отнимает слоты у клиентов.
- Служба проверяет процесс по командной строке: устаревший pidfile после
  перезагрузки не мешает старту, `stop` не трогает чужие процессы.
- `Telegram=vpn` при ограниченном `port_proxying.lst` добавляет UDP 590:600 и
  1400 для звонков.

### Рекомендация

Обновите `nfqws2-keenetic` до 1.3.2: там исправлены стратегия UDP без
`blob`, ложное «сервис работает» при старом процессе и повторная установка
правил iptables.

## 3.1.1 — 22.10.2026

### Исправлено

- Импортированный профиль Discord Voice убирал UDP 443 из `UDP_PORTS`: в
  NFQUEUE оставались только порты профиля (`19294:19344,50000:50100`), и
  QUIC-профили YouTube и `user.list` не получали пакетов. QUIC к Google
  блокировался, а приложение YouTube на телефонах переставало работать, хотя
  сайт в браузере открывался по TCP. Теперь при импортированном профиле Voice
  `UDP_PORTS` — это `443` плюс порты профиля. Чтобы исправить уже
  записанный конфиг, достаточно один раз выполнить apply любого маршрута.

## 3.1.0 — 21.10.2026

Проверено на Keenetic Giga (MT7621): XKeen 2.0 с Xray 26.10.17,
`nfqws2-keenetic` 1.3.1 (ядро v1.0.5.2), Python 3.13 из Entware.

### Маршруты

- Discord разделён на два независимых маршрута: **Discord TCP** (домены,
  TCP/TLS и QUIC) и **Discord Voice** (UDP-порты Voice/STUN). Флаги
  `--discord-tcp-route` и `--discord-voice-route`; прежний `--discord-route`
  переключает оба.
- **Telegram** — четвёртый сервис, по умолчанию не управляется (`unmanaged`).
  Режимы `direct`, `vpn` и `ws`. Подробно — [docs/TELEGRAM.md](docs/TELEGRAM.md).
- Режим **`ws`**: MTProto клиентов прозрачно уходит в ретранслятор на роутере
  (`tools/router/telegram_ws_relay.py`, служба `S99kdn-telegram-ws`) и идёт
  внутри WebSocket, как у Telegram Web и tg-ws-proxy. Пути по очереди: прямой
  WebSocket (DC2/DC4), через Cloudflare (`kws{N}.<домен>`, если провайдер
  блокирует адреса Telegram), прямой TCP. Клиентов настраивать не нужно.
  Ретранслятор держит заранее открытые WebSocket, обходит заблокированные
  адреса Cloudflare, выбирает быстрые домены и адреса, сам проверяет прямой
  путь в фоне; `--self-test` проверяет все пути с роутера. Свои домены и
  адреса Cloudflare — `telegram-ws-domains.txt` и `telegram-ws-cf-ips.txt`
  в `/opt/etc/keenetic-discord-nfqws2/`.
- Режима `zapret` у Telegram нет: при блокировке по адресам он не помогает.
  Записанный `Telegram=zapret` переводится в `direct` при следующем apply.

### Автоподбор

- Можно выбрать конкретный BAT-файл Flowseal; перебор с глубиной строится от
  него, а в логе указан BAT-файл каждого кандидата. Seed генерируется на
  роутере, в панели его нет.
- Автоматическая проверка Discord Voice: по трафику самого клиента (новый
  поток с discovery-пакетом и ответами сервера), с запасными вариантами
  «вручную» и «пробный звонок»; больше вариантов Voice-стратегий.
- Автоподбор только для Discord TCP, Discord Voice и YouTube.

### Панель

- Новый дизайн; карточки четырёх сервисов, у Telegram — Direct, VPN, WS, Выкл.
- Лог задания: сначала итог, затем пояснения безвредных строк, затем вывод.
- Фоновые задания не запускаются дважды; кнопки и вкладки не застревают;
  панель отвечает даже на повреждённые сохранённые данные.

### Исправления

- Откат после обновления пакета nfqws2 больше не возвращает старые Lua-файлы
  рядом с новым ядром: при расхождении версий восстанавливаются только данные.
- Xray: правила проекта не расширяются на чужие правила; уникальные `ruleTag`
  (Xray не запускается при повторяющемся теге); корректное снятие комментариев
  JSONC.
- Переключение маршрутов через обёртки сохраняет настройки Discord UDP.
- Откат к baseline после первой установки в режиме без XKeen.
- Второе нажатие «Стоп» в автоподборе больше не оставляет nfqws2 остановленным.
- Windows-тюнер: вердикт Voice берётся из результата, QUIC-опции YouTube не
  попадают в TCP-профиль, имена BAT-файлов не на латинице кэшируются.
- Диагностика отмечает настройки, удалённые в Xray 26.10.

### Разработка

- Единый запуск тестов `sh tests/run-all.sh` (shell под busybox/dash, pytest,
  Playwright), CI с shellcheck и ruff; отчёт ревью — [docs/CODE-REVIEW.md](docs/CODE-REVIEW.md).
